# OLMO 32B shows RL produces new capabilities

## Background

[Yue et al 2025](https://arxiv.org/abs/2504.13837) claims that RL merely sharpens a models existing capabilities, improving the likelihood of a successful response on a single try while reducing the likehood that a model succeeds if ggiven many tries (ie, improves pass@1 at the expense of pass@k where k is large, like 256+). Personally, this feels obviously wrong. In particular, if you do enough RL with a reasonable learning rate in an environment with fairly variable rewards, you can get a model trained on one task (like image recognition) to do something wholely unrelated (like playing chess). So the strong version of this claim has to be wrong, and the original paper also freely notes that its claims applied to very low compute budgets (around 0.01% of the total training devoted to RL) which is way less than modern frontier models get.

The [ProRL paper](https://arxiv.org/abs/2505.24864) finds the obvious result. If you do more RL, and do it well, you'll get new capabilities even using the criteria of 'the post-RL model can succeed with pass@1 where the pre-RL model fails with pass@256'. They note that their results were somewhat limited, and the models trained were better at formatting, with it not being 100% clear that RL gave new interesting capabilities beyond format following. ProRL also didn't do a 'ton' of RL, only about [2% or less of its compute budget](https://github.com/chainik1125/nd-rl/blob/dan/docs/literature/2026-11-06-olmo-novelty/REVIEW.md). This is much less than DeepSeek V3.2, which [claims upwards of 10% budget on RL](https://github.com/chainik1125/nd-rl/blob/dan/docs/literature/2026-11-06-olmo-novelty/REVIEW.md) (although they don't say how much of their compute budget is spent distilling off of Claude & ChatGPT, so take these figures with a grain of salt).

I'm gonna be talking about 'creating capabilities' in this post, and to be [extra pedantic](https://github.com/dan-pandori/dan-pandori-blog-reports/blob/main/posts/elicitation-vs-emergence/README.md) I mean improving success rate for a given compute budget.

## Results for OLMO 32B

OK, so small amounts of RL (sub 0.1%) can maybe be described improving pass@1 at the expense of pass@k. But lots of RL (more than 2%) seems like it is capable of installing new capabilities. It would be really cool to have a near frontier scale model, which had pre-training and RL steps, and which open sourced the weights as various checkpoints, so that we could test before & after RL. OLMO 32B fits the bill exactly.

So I had Claude run some experiments to see if there are evals & problems where the pre-RL model does poorly, but the post-RL model does well ([1](https://github.com/chainik1125/nd-rl/blob/dan/experiment-summaries/2026-11-03-olmo-rlzero-pilot-base-credited-on-all-17-rl-only-solves-within-383-samples-reach-0-at-k512-verdict-inconclusive/README.md), [2](https://github.com/chainik1125/nd-rl/blob/dan/experiment-summaries/2026-11-03-olmo-think32b-one-reach-candidate-dpo-credited-7-in-256-by-rl-verifier-states-answer-once-verdict-inconclusive/README.md), [3](https://github.com/chainik1125/nd-rl/blob/dan/experiment-summaries/2026-11-04-olmo-ifomega-reach-on-ifbench-49-strict-43-hand-and-ifeval-6-omega-test-out-inconclusive/README.md)). Some of the early attempts were on datasets that were mostly saturated before RL, so no interesting results there. But [IFBench](https://artificialanalysis.ai/evaluations/ifbench) showed promise, with a pre-RL score of 0.280 and a post-RL score of 0.676 (a pretty big change!). The experiment protocol called for testing the pass@256 (and sometimes pass@1024) for the base model, for examples where the post-RL model successfully solved something that the base model failed for pass@8. This still had quite a few successful examples.

Claude, to its paranoia & credit, was worried about checker gaming. So it tested the answers to make sure they followed the spirit of the prompt, in addition to the hard constraint (ex. making sure a request for a screenplay actually had some sort of plot, in addition to obeying the constraint to have each sentence have one more word). IMO Claude was if anything overly strict in its application of what constitutes gaming (ie, an edge case to it was whether or not to allow a Chinese poem for a prompt that requested a poem without any 'e's, where IMO this is both brilliant and hilarious). You can view some examples [for yourself here](https://github.com/chainik1125/nd-rl/blob/dan/docs/writeups/2026-11-07-ifbench-gamed-vs-genuine/README.md).

So we get that RL can improve the model's ability to accomplish some sets of tasks for a given budget, and does that without necessarily harming pass@k. This does not surprise me, but it was fun to extra show that the Yue 2025 paper's inability to get capability emergence was some combination of low RL budget + possibly bad RL techniques (I haven't thought hard about the latter, and I'm definitely not claiming I could do better [just that labs/OLMO 32B's authors/etc do better]).

OK, but is this novel/publication-worthy? Frankly I don't personally think so. I think Yue 2025 was interesting because it was surprising (RL doesn't make capabilities, it just does this weird elicitation thing!). Showing that RL actually 'does' create capabilities is IMO the boring & normal thing (if RL didn't make capabilities, how do RL-only models like AlphaZero work, for example). But we can (tell Claude to) do [some analysis of the novelty of these results](https://github.com/chainik1125/nd-rl/blob/dan/docs/literature/2026-11-06-olmo-novelty/REVIEW.md).

Some bits that I found particularly enjoyable about this literature comparison:
1) ProRL finds that the gains for capabilities are strongest where the pre-RL model was weakest. This is true & replicates for us, but is mostly true for boring definitional reasons. Ie, if the pre-RL model already scores 0.4, the 'gain' is at most 0.6. A more interesting result would have to look at log-success probabilities, otherwise this is a bit of a silly (but true) statement. Claude noted that the correlation would have been stronger if the pairings were randomized, to really show that it just has to do with the way the metric is computed, rather than anything interesting.
1) [Yang 2026](https://arxiv.org/abs/2610.34894) tested many different models before & after RL. They noted that RL consistently improves a models reliability (measured by pass@1), its ability to answer in the allotted time (runs out of budget less often), and only rarely improves a models reach (ie, its ability to finish problems that the prior model was incapable of solving). Overall I agree with this result, but mostly because the pre-RL models saturate or nearly saturate the average dataset, so there is little for the post-RL model to do better on. The experiments we did show some reach, but I really did have to look around to find some datasets that would demonstrate reach, the average dataset would not.

Overall this was a very fun round of experiments. IMO the most interesting I've done for [the SPAR project](https://sparai.org/projects/f26/rec8qbsiN63iT3e8Z/) so far, and I fully intend to pursue this line of inquiry further.

## Is OLMO 32B better at thinking?

Almost certainly. To further test this, we gave the DPO model (ie, just before RL) the post-RL'ed model's scratch work and [tested if the DPO model could get the right answer on IFBench prompts that it previously failed on](https://github.com/chainik1125/nd-rl/blob/dan/experiment-summaries/2026-11-08-olmo-transplant-dpo-given-rl-thinking-0p14-vs-rl-0p92-genuine-on-41-ifbench-reach-prompts-readings-partly-and-graded/plain_summary.md). With these notes, the RL'ed model succeeds 92% of the time, the DPO model 14% of the time. This is extra embarrassing for the DPO model because the scratch notes often include a verbatim passing answer, which the DPO model would fail to correctly transfer (or perhaps it didn't trust the answer, hard to be confident w/o some mech interp that is fancier than I know).

The notes were generally quite helpful though. Without notes, the RL model only succeeds 8% of the time (and giving it the DPO model's notes from a failed attempt lowers success to 6%). Trimming the notes (cutting off some fraction of the end of the notes) did gradually reduce performance, in a manner roughly compatible with the notes giving useful direction (rather than one big useful gestalt only functional as a whole).

If we tell the pre-RL model to 'answer in at most 60 words' as a brevity hint, [about a third of the post-RL'ed successes are also reachable by the DPO model](https://github.com/chainik1125/nd-rl/blob/dan/experiment-summaries/2026-11-06-olmo-iffu-brevity-hint-elicits-dpo-on-15-16-of-48-if-reach-prompts-10-of-10-survive-1024-draws-token-budget-on-1-of-3-geometry/README.md). So some of what the RL model learns is to be brief, at least if there are hard rules that must be obeyed (since it is often easier to obey hard rules for a shorter output).

## How about OLMO 7B?

Less strong results. The RL'ed model [mostly seems to be gaming the checker rather than producing valid & interesting responses for IFBench](https://github.com/chainik1125/nd-rl/blob/dan/experiment-summaries/2026-11-08-olmo-rlzero-if-rl-zero-games-if-checkers-94pct-ifbench-hand-reach-5-format-prompts-ifeval-inconclusive/plain_summary.md).  Claude puts this as without SFT, RL doesn't add real capabilities. And that is possible, but it is also fair to say that 32B is a much larger model with noticeably different training, and the absence of SFT from the 7B training was merely one such change.
